# Specification

What [Project Name] does, as it exists in production right now.

This document is updated in place, by the proposals in this directory. It is
descriptive, present-tense, and free of rationale — the reasoning behind any
given requirement belongs in the proposal that introduced it.

## Context

Who the system is for and what problem it solves. The actors — human and
machine — that interact with it, and the external systems it depends on.

## Behaviors

What the system does, as a numbered list of testable statements. Each MUST be
falsifiable. A reader should be able to say whether the running system satisfies
it. "The system is fast" is not a behavior. "Search results return within 300ms
at the 95th percentile" is.
